# 0.5.2 — El commit se busca en el `cd` correcto y no en el texto de un script

- **Fecha**: 2026-11-21 · **Commit**: ver el tag `session-handoff-v0.5.2` · **Tipo**: fix
- **Visto en**: una sesión de Claude Code que trabajaba en un worktree y escribía tests con heredocs

## Síntoma

Dos avisos de hash falsos en la misma sesión:
1. `cd <checkout> && git fetch && git worktree add … && cd <worktree> && … git commit -q` pidió anotar el HEAD del
   checkout principal (`3af2d56`) en lugar del commit hecho en el worktree.
2. Un `python - <<'EOF'` cuyo texto incluía `&& git commit -q` se tomó como un commit y pidió anotar el HEAD de `dev`.

## Causa

1. `commitDir` tomaba el **primer** `cd X &&` del comando, no el último antes del `git commit`.
2. `isCommit` buscaba `git commit` en todo el comando, también dentro de heredocs y de texto entre comillas.

## Cambio

- `commitDir` sigue los `cd` en orden hasta el `git commit` (un `cd` relativo parte del anterior) e ignora los que
  vienen después.
- `isCommit` y `commitDir` analizan el comando sin el cuerpo de los heredocs y con el texto entre comillas en blanco.

## Prueba

`hooks/handoff.test.ts`: casos nuevos en `the commit runs where its git -C or cd points…` (dos `cd`, `cd` relativo,
`cd` después del commit) y en `a commit is detected in a compound command…` (heredoc, `printf` con el texto y un
commit real con heredoc). Los dos tests fallaron antes del cambio.

## Lección

Un comando de shell no se analiza como texto plano: los heredocs y las comillas son datos, y los `cd` cambian el
directorio en orden.
