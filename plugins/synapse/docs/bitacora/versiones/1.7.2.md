# 1.7.2 — Synapse corre en Claude Code en Windows, y `--help` de un CLI de agente no pide confirmación

- **Fecha**: 2026-11-21 · **Tipo**: fix
- **Visto en**: Claude Code en Windows (este repo) y un proyecto con Codex en Windows

## A. Claude Code en Windows: los hooks no corrían

### Síntoma

Cada Edit, Write y Bash mostraba `PreToolUse:Edit hook failed` con "no se encontró Python; ejecutar sin argumentos
para instalar desde el Microsoft Store…". Synapse no revisaba nada: un hook que falla no bloquea (falla abierto).

### Causa

`hooks/hooks.json` llamaba `python3 "${CLAUDE_PLUGIN_ROOT}/hooks/<hook>.py"`. En Windows, `python3` resuelve al
acceso directo de Microsoft Store (`WindowsApps\python3.exe`, exit 49) aunque haya un Python real como `python` o
`py`. Además, el lanzador `run-hook.cmd`, que sí busca un Python real, siempre salía con 0 (correcto para Codex y
Antigravity, que leen JSON) y perdía el exit 2 con que Claude Code bloquea.

### Cambio

- `hooks/hooks.json`: cada hook pasa por `"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" <hook>`. En Linux y macOS el
  bloque `sh` del lanzador hace `exec` del mismo `python3`, así que la salida no cambia (golden idéntico).
- `run-hook.cmd`: sin `--host` (Claude Code) devuelve el exit del hook; sin Python, emite `ask` en vez de nada;
  fija `PYTHONIOENCODING=utf-8` para que el stderr no llegue en cp1252.

### Prueba

- `tests/unit/test_launcher.py`: `hooks.json` no llama `python3` directo, el lanzador conserva el exit 2 y el UTF-8
  de `🚫 BLOCKED · Synapse`, y sin Python responde `ask`.

## B. `codex exec --help` pedía confirmación

### Síntoma

El agente quiso saber qué CLI tenía disponibles (`Get-Command codex,claude`) y luego consultó la ayuda con
`codex exec --help`. Synapse respondió `ask` con `structure.agent_wrapper` ("lanza otro agente en modo no
interactivo"), y el agente quedó esperando que el usuario ejecutara `synapse.py approve`.

### Causa

`agent_wrapper` solo miraba si el primer o segundo token era el modo no interactivo (`exec`, `-p`, `run`…). Con
`--help`, `-h`, `--version` o `-V`, el CLI imprime su ayuda o su versión y sale sin correr ningún agente.

### Cambio

- `block_dangerous.AGENT_INFO_FLAGS`: si el comando lleva uno de esos flags, `agent_wrapper` no lo trata como un
  agente lanzado. `codex exec 'prompt'` sigue en `ask`, y con `--dangerously-*`/`--yolo`/`--full-auto`, en `block`.

### Prueba

- `tests/cases/block_dangerous.json`: `pass_agent_wrapper_help_runs_no_agent` (`codex exec --help`) y
  `pass_agent_wrapper_version_runs_no_agent` (`claude -p --version`), con `expected_decision: null` y su golden
  generado en WSL.

## Lección

- Un hook de Claude Code nunca llama `python3` directo: en Windows puede ser el acceso directo de la tienda. Todo
  host pasa por `run-hook.cmd`, y la vigilancia trata un `hook failed` como hallazgo aunque el agente siga avanzando.
- Antes de detener a un agente en Codex, la regla debe confirmar que el comando hace lo que teme. Un flag
  informativo no lanza nada.
